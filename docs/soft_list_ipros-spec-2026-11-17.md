# ソフト営業リスト（ipros由来）仕様 — 2026-11-17 本人指示

条件の正本は条件書「01_soft-list-spec」（2026-11-17）。この文書は、その条件を Researcher の実装
（researcher/build_soft_list.py ＋ researcher/topics/soft_list_ipros.yaml）にどう写したかの記録。
条件を変えるときは条件書とこの文書の両方を直す。

## 前提（条件書0章・動かせない）
- 元データは ipros_all（Drive、約45,108社）だけ。検索で社名を足さない（検索は判定の裏取りだけ）。
- 売る先：ものづくり企業・デザイン会社・建築事務所。規模：従業員100〜500人。大手は入れない。
- 優先：AM未使用（A）→試験的（B）→事業として使用（C）の順。
- 出力は公式URLとメールアドレスだけ（無ければ問い合わせフォームURL）。推測で作らない。
- キーワード一致だけで入れない。公式サイトの事業内容を読み、引用つきで判定する。引用が無ければ名簿に入れない。
- 数を合わせるために条件を緩めない。

## 第1段（種・build_soft_list.seeds_from_drive）
- ipros_all.csv の行そのものから社名を取る。キーは ipros_url の company/detail の数字（ipros_id）。
  文字列の断片から会社を作らない（2026-11-11 監査の失敗型1への対応）。
- 役割 R1〜R11 の候補拾い：category・info・product の文に、役割ごとのキーワード集合
  （ROLE_PATTERNS、条件書2章の表の写し）が当たるか。当たった役割はすべてタグとして記録する。
  ここは候補までで、確定は第2段。
- 従業員：employees が読めて 100〜500 の範囲外なら足切り（理由を seeds.csv に記録）。
  空欄・範囲またぎ（100〜500 の境界をまたぐ表記）は落とさず第2段へ回す。空欄の割合は stats.md に出す。

## 第2段（1社ずつ・build_soft_list.check_one_soft）
- 公式サイトの取得と会社概要の読みは build_award_chain.check_one を流用する
  （その会社自身の ipros 掲載ホームページから始める。他社の属性を写さない＝失敗型5への対応）。
- 従業員数：公式の会社概要の引用を正とする。読めなければ ipros の記載を使い、出典を「イプロス」と記録する。
  どちらでも確定できなければ人数不明として門番で落とす。
- 役割の裏付け：候補の役割のパターンが公式サイトの事業内容に当たるか。当たらなければ役割は消え、
  残らなければ名簿に入らない（共起だけで証拠にしない＝失敗型2・3への対応）。
- AM判定 A/B/C：公式サイトの本文（トップ＋事業・製品・サービス・設備・事例ページ、最大7ページ）を読み、
  AM の言葉のある行を探す。受託・サービス・量産などの事業の言葉と同じ行にあれば C、
  形跡はあるが事業の言葉が無ければ B、読んだ範囲に形跡が無ければ A（根拠は事業内容の引用＋「形跡なし」の記録）。
- 上場・大手の完全子会社：会社概要まわりの文から「上場・証券コード・市場名」「完全子会社・グループ会社です」
  の形跡だけを記録する。形跡のある会社は記録シート（checked.csv）に残し、名簿には入れない。断定はしない。
- 連絡先：公式サイトのメール（先頭1件）と問い合わせページURL。推測で作らない。

## 門番（verify_list.verify・条件は build_soft_list.CONDS に明記）
通過には次の4条件すべての引用が要る。1つでも欠ければ外し、理由を verify.md と checked.csv に残す（捨てる経路）。
1. 従業員100〜500（出典つき）
2. 役割の裏付け（公式サイトの事業内容の引用）
3. AM判定の引用
4. 上場・大手完全子会社でない

## 出力
- researcher/out/soft_list_ipros/seeds.csv（第1段：候補と足切り理由）
- researcher/out/soft_list_ipros/checked.csv（記録シート：第2段で調べた全社と全引用）
- researcher/out/soft_list_ipros/list.csv（名簿：門番通過分）
- researcher/out/soft_list_ipros/stats.md（集計：役割×判定の社数表、足切りで落ちた数、連絡先が取れなかった数、従業員空欄の割合）
- researcher/inputs/soft_list_ipros.csv（通過分の社名・公式URL・文脈。第2段の会社調査の入力）
- Drive スプレッドシート「ソフト営業リスト（ipros由来）」（名簿タブ＋記録タブ）への書き出しは
  GitHub Actions では行わない。リポジトリに Google の書き込み資格情報が無く、ダウンロード専用だから。
  出力（list.csv／checked.csv）が着地したら、Claude 側でスプレッドシートを作ってこの文書に ID を追記する。

## 運用
- control.yaml には run: false で登録する。回し始め（run: true への切替と初回の着地確認）は GitHub 側の担当の手順。
- 1回の実行は90分で区切り、checked.csv の続きから再開する。全候補が終わると BUILD_DONE が立つ。

## am_soft_peers_jp との関係（2026-11-17 確認）
- am_soft_peers_jp は run: true だが inputs/am_soft_peers_jp.csv が無く、出力も無い。一度も回っていない。
- 原因の見立て：plan.py の remaining() は入力CSVを素の open() で読み、例外処理が無い。
  入力の無い run: true テーマが1つあると plan.py 全体が落ち、researcher.yml の plan ジョブが失敗して
  調査レーン全体（research ジョブ）が止まる。build レーンは別ジョブなので名簿づくりは動き続ける。
  customer_eye_a〜d（2026-11-15 追加）に出力が無いこととも符合する。
- 直すかどうか（入力CSVを置く／run: false にする／plan.py に例外処理を足す）は本人の判断。ここでは直さない。
